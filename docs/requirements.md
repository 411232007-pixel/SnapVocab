# 拾物單字簿 SnapVocab：需求文件

版本：v0.1  
狀態：需求規劃，尚未代表已完成實作。  
建議存放位置：docs/requirements.md

## 1. 專案目標

開發一個在個人電腦上執行的 Discord Agent。使用者拍攝生活中的物品並上傳至指定頻道，系統辨識物品，回傳中文名稱、英文單字與日文單字，並將結果存入該使用者的個人單字紀錄。使用者可以透過指令查看歷史紀錄，並下載只包含自己資料的 Excel 單字簿。

英文與日文由同一個 Discord Bot 提供，預設同時顯示，不需要分成兩個 Bot。

## 2. 使用範圍

- 主要辨識日常可見的實體物品，例如杯子、雨傘、桌子、椅子、書包及文具。
- 第一版主要處理單張照片中的一個目標物品。
- 若照片內有多個明顯物品，先列出候選供原上傳者選擇，或請其指定位置、裁切後重傳；不可自行把所有東西大量加入單字簿。
- 若無法判定物品，請求更清楚的照片或文字補充，不硬猜。
- 不要求辨識品牌、商品型號、真實人物身分或專業零件的精確名稱。
- 第一版不要求語音播放、測驗、網站介面、定時通知或圖片永久保存。

## 3. 核心流程

1. 接收指定 Discord 頻道中的圖片附件。
2. 驗證圖片格式、大小與實際內容，顯示處理中狀態。
3. 辨識物品；有歧義時先請使用者確認。
4. 根據確認的物品產生中文、英文及日文詞彙資料。
5. 驗證結果欄位與合理性，回覆雙語單字卡。
6. 將成功結果連同使用者 ID、查詢時間保存，供日後查閱及 Excel 匯出。
7. 清理暫存圖片；處理失敗時回覆可理解的原因，不寫入假結果。

## 4. 單字卡內容

| 欄位 | 需求 |
| --- | --- |
| 紀錄 ID | 每筆成功查詢的唯一識別碼 |
| 中文名稱 | 物品的繁體中文名稱 |
| 英文單字 | 符合照片語意、常見自然的名稱，必要時可用詞組 |
| 英文詞性 | 依此處用法標註，例如名詞 |
| 英文例句 | 一句簡短、適合初學者且符合物品語意的例句 |
| 英文例句中譯 | 繁體中文翻譯 |
| 日文單字 | 常見自然的日文寫法，不強求一定使用漢字 |
| 日文假名 | 漢字詞標注讀音；外來語保留標準片假名 |
| 日文羅馬字 | 使用一致的常見羅馬字轉寫方式 |
| 日文例句 | 一句簡短、自然且適合初學者的例句 |
| 日文例句中譯 | 繁體中文翻譯 |
| 語意說明 | 必要時簡短說明物品種類或近義詞差異，例如 mug 與 cup |
| 查詢時間 | 以 Asia/Taipei 顯示，包含時區說明 |

品質規則：

- 以照片中的具體意思翻譯，不僅對中文名稱逐字翻譯。
- 英文原則上使用單數基本形式；通常使用複數的詞如 scissors，依正常用法呈現。
- 日文讀音需與所顯示的單字對應；詞性與例句使用方式應一致。
- 不強求英日文詞彙一對一；有涵義或範圍差異時加以說明。
- 優先提供一個最適合當下物品的常用詞，必要時補充少量近義詞，避免一次堆砌大量詞彙。
- 無法確定的細分類應退回可確認的一般名稱，並說明限制，不捏造品牌、材質或用途。
- 如使用辭典或外部來源查證，附上實際來源；沒有查證時不得宣稱已查閱辭典或提供假網址。
- 視覺辨識與翻譯仍可能有誤，使用說明應簡短說明此限制。

## 5. 指令與互動

第一版建議採以下文字指令；若實作採用其他指令形式，須在架構規劃時說明並保持文件一致。

| 操作 | 預期結果 |
| --- | --- |
| 上傳圖片 | 辨識物品，回傳單字卡並保存自己的紀錄 |
| 置頂使用說明 | 不設 `!說明` 指令；Bot 啟動時在頻道發佈並置頂說明訊息，內容含操作方式、支援內容、個人資料範圍、匯出方式及一次只辨識一張的限制 |
| `!最近` | 顯示自己最近十筆成功查詢，包含紀錄 ID、中文、英文與日文 |
| `!單字 紀錄ID` | 從資料庫取出自己的指定紀錄，回傳完整單字卡，不重新呼叫模型生成 |
| `!匯出` | 產生並傳送只包含自己紀錄的 .xlsx 檔案 |
| `!統計` | 由程式計算自己的成功查詢次數及不重複單字數 |

沒有紀錄時，!最近、!統計與 !匯出 都應清楚提示尚無紀錄，不報錯或產生誤導結果。

## 6. 個人紀錄與統計

- 使用 Discord user ID 作為資料擁有者識別，不以可能重複或變更的暱稱作為唯一依據。
- 保存紀錄 ID、user ID、查詢時間、物品中文名稱、完整雙語單字卡與必要辨識狀態。
- 每次成功查詢各留一筆歷史紀錄，即使是同一物品也不覆蓋先前紀錄。
- 成功查詢次數為成功保存的歷史筆數；失敗或等待確認的查詢不計入。
- 不重複單字數依程式正規化後的英文基本名稱與日文標準名稱組合計算，去除前後空白並統一英文大小寫；不宣稱能自動合併所有同義詞。
- 計數與去重由程式完成，不由語言模型估算。
- 重新啟動 Bot 後，紀錄仍可查詢、統計及匯出。
- 紀錄查閱、候選確認及匯出都必須驗證操作者身分，不能透過猜紀錄 ID 取得他人資料。

## 7. Excel 匯出需求

### 7.1 使用者操作

使用者輸入 !匯出，系統根據該次指令發送者的 Discord user ID 讀取資料、產生 Excel，並以 Discord 附件提供下載。不是只在電腦本機產生檔案或回覆本機路徑。

每次匯出為一份當下資料的快照，不承諾已下載的 Excel 會自動更新。

### 7.2 工作表

工作表一：單字簿

- 每個不重複單字組合一列，包含中文名稱、英文單字、英文詞性、英文例句及中譯、日文單字、假名、羅馬字、日文例句及中譯、語意說明、首次查詢時間、最近查詢時間及查詢次數。
- 重複單字的欄位內容採最近一次成功紀錄，首次時間與查詢次數由全部相關歷史計算。

工作表二：查詢紀錄

- 每次成功查詢各一列，保留紀錄 ID、查詢時間與該次完整單字卡，方便回顧歷次結果。

### 7.3 格式與檔案處理

- 檔案格式必須是標準 .xlsx，不是把 CSV 改副檔名。
- 標題列加粗，凍結首列，開啟篩選，依內容設定合理欄寬，例句等長文字自動換行。
- 中、英、日文可正確顯示；時間統一顯示 Asia/Taipei，欄名或說明註明時區。
- 匯出檔名包含安全的使用者識別與時間，暫存檔使用唯一名稱，避免多人同時匯出時覆寫或拿錯檔案。
- 不使用暱稱直接拼接檔案路徑；清洗檔名並處理 Excel 公式注入，文字欄位必須以文字保存。
- 不包含 Token、原始圖片、他人的紀錄或非必要個資。
- 產生後實際檢查工作表、列數、欄位與個人資料範圍，再傳送附件；無需呼叫語言模型產生 Excel。
- 傳送完成或失敗後清理匯出暫存檔，不影響永久保存的單字資料庫。
- 超過 Discord 實際附件限制時，應分檔或提示可行處理方式，不無限重試。

### 7.4 回覆位置與隱私

預設在使用者執行指令的頻道回傳自己的單字簿，符合課堂在頻道展示處理結果的情境。使用說明須寫明：依帳號分開資料不等於附件只有本人看得到，有頻道權限的人仍可能下載該附件。不要宣稱公共頻道回覆是私人訊息。

## 8. 執行環境與安全要求

- 在 Windows PowerShell 操作，優先使用 Python 3.12、uv、Discord Gateway Bot；實際套件及版本在架構規劃時確認。
- 優先使用簡單的本機持久化資料庫，例如 SQLite；Excel 是匯出成果，不要求作為即時主資料庫。
- 只監聽 .env 中 CHANNEL_ID 指定的頻道，忽略其他 Bot 和自己的訊息。
- Token 與必要金鑰放在本機環境設定；提供 .env.example，不含真實機密。
- 第一次 commit 前設定 .gitignore，排除 .env、使用者資料庫、日誌、圖片、Excel 暫存檔與虛擬環境。
- 限制圖片格式、檔案大小、解碼後尺寸、單人頻率、總並行數及逾時，於架構文件記錄數值。
- 圖片與使用者文字視為資料，不得當成覆蓋系統行為的指令。
- 模型輸出驗證結構、必要欄位、型別與長度；資料庫操作採參數化查詢。
- 如使用 claude -p，在單筆隔離暫存資料夾執行並限制工具權限，不得讀取 .env 或任意執行系統命令。
- 下載來源受限制，避免任意網址造成內部網路或本機資源存取。
- 不把錯誤堆疊、Token 或其他機密直接發到 Discord；避免非預期的 @everyone 等 mention。
- 同時收圖、匯出時保持 Bot 可回應，避免耗時工作阻塞 Discord 連線。
- 預設不永久保存原圖；只保留單字簿所需的結構化資料。
- 圖片理解及雙語生成工具須先確認可用性、登入狀態、必要權限與費用；不假設使用者已有額外付費 API，不自行購買服務。

## 9. 驗收案例

1. 上傳清晰的雨傘照片，得到對應中文名稱、umbrella、傘及正確讀音與簡短例句。
2. 上傳另一件生活物品，得到不同的正確單字卡。
3. 照片包含多個物品時可確認目標，只有原上傳者能完成該次選擇。
4. 模糊、非圖片、不支援格式、過大圖片或模型逾時都有明確回覆，且不加入成功紀錄。
5. !最近 與 !單字 可以取回前面的結果；重啟後仍存在。
6. 同一帳號查詢相同詞彙兩次，查詢次數增加，去重單字數不增加。
7. !匯出 在 Discord 提供可下載並可正常開啟的 Excel，兩張工作表、列數及文字內容符合規則。
8. 兩個帳號各查不同物品並各自匯出，檔案只含各自資料；同時匯出也不混檔。
9. 未有紀錄時，各查詢及匯出指令能正常提示。
10. 英日文與例句在 Excel 顯示正常，長文字可閱讀，公式樣式的外來文字不作為公式執行。

## 10. 作業對應與文件

| 評分方向 | 預計功能 | 展示方式 |
| --- | --- | --- |
| 基本處理結果 | 收圖、辨識、回傳雙語單字卡 | 上傳生活物品照片 |
| 運算 | 查詢次數、單字去重數、各單字查詢次數 | 重複查詢後執行 !統計 或查看單字簿 |
| 調用前面的結果 | 查詢歷史、舊單字卡及歷史匯出 | 執行 !最近、!單字、!匯出 |
| 分人處理 | 按 user ID 分開紀錄及匯出 | 兩個帳號分別操作 |
| 其他功能 | 回傳 Excel 單字簿附件 | 實際下載並檢查 .xlsx |

此表是功能規劃與評分方向的對應，不保證分數，最終以 Scorer 與老師判定為準。

- 建立符合課程規範的獨立新 public GitHub repository，不 fork 或沿用老師及同學的 commit 歷史；主題是否被佔用須依課程提交結果確認。
- repository 與歷史 commit 不得含任何真實 Token 或金鑰。
- 文件包含 docs/requirements.md、docs/architecture.md 及 README.md。
- README 列出實際完成功能、安裝、設定、啟動、指令、資料與附件可見範圍、限制及展示步驟。
- /ready 與 /done 為老師 Scorer 指令，本 Bot 不實作。

## 11. 開發階段與下一步

1. 先以幾張真實生活物品圖片確認辨識與英日文輸出品質。
2. 完成 Discord 收圖、單字卡與個人紀錄保存。
3. 完成歷史查詢、統計與 Excel 匯出。
4. 驗證多人隔離、失敗處理、檔案內容與真實 Discord 展示，更新文件完成狀態。

請開發 AI 先閱讀本文件、檢查專案與現有工具，整理需求理解，建立 docs/architecture.md，說明圖片理解、雙語生成、資料保存、Excel 生成及 Discord 互動方案，列出套件、設定、費用與待確認事項。若資料夾已有舊專案，先盤點可沿用內容及衝突，不要直接覆蓋舊資料庫或刪除檔案。先不要安裝套件或撰寫功能程式，等使用者說「開始」後再實作。
